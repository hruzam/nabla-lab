## Required records

| Record | Minimum content | Why it matters |
|---|---|---|
| Case | ID, target, evidence references/digest, missing evidence, related-case group | Reproducibility and leakage-resistant splits |
| Question | ID, exact wording, primitive, options/criteria, predicate meaning, rubric version | Detect semantic changes across rephrasing |
| Execution | Requested/returned model, provider/endpoint, request ID, timing, input size, billed cost if known | Separate documentation from exercised behavior |
| Receipt | Raw output reference, validity, normalized distribution where applicable, provider statistic | Preserve raw observations before interpretation |
| Interpretation | Threshold/calibration version, FACE/TAIL/EDGE, orientation source or missingness | A harness decision must not masquerade as a model field |
| Composition | Rule/version, fixed and unresolved predicates, endpoint results, pivot algorithm and set | Make the theorem's preconditions inspectable |
| Acquisition | Available actions, selected action and cost, new evidence, target changes, loop history | Test why an additional call was useful |
| Outcome | Human/independent label, adjudication method, disposition, later correction, missing outcome | Distinguish valid output, use and truth |

Do not flatten timeout, malformed response, unsupported primitive, insufficient evidence, support/refutation conflict and ordinary EDGE into one numeric score. Keep model probabilities separate from fitted reliability and action loss.

## Deterministic responsibilities

Validate names/types, option correspondence, finite ranges and distribution normalization with declared tolerances. Preserve immutable request/receipt references and explicit supersession. Batch questions whose wording does not depend on another answer over the same state; a dependent follow-up gets new question provenance. Scope budget, retry and uncertain-send recovery to the implementing contract; default SDK retries must not silently defeat its accounting.

Check monotonicity and boundary conditions for a small explicit rule. Evaluate both endpoints. Find potential pivots using a documented algorithm; do not assume two endpoint evaluations return the pivot set. If the task requires self-duality, test it separately. A conditional certificate is only as sound as the fixed predicate assignments and the rule's match to the task.

Maintain a no-progress detector and finite resource limit for acquisition. Changed option sets or predicates must either preserve the original meaning under an explicit mapping or open a new rule/evaluation. No convergence claim follows from repeatedly asking an uncertain model.

## Corrections to carry into design

- A monotone simple game need not be a weighted threshold; odd size alone provides no general decisiveness.
- Binary Choice margin and current Choice confidence coincide; neither supplies an independent calibration measurement.
- EDGE polarity yields four atomic cases, or a tagged orientation field. A near-tie alone supplies no polarity.
- An explicit third categorical option is not inherently ordered. Compare it only when its meaning and labels are defined.
- Fixed-confidence errors can pass the endpoint certificate. Track end-to-end decision outcomes.
- Pivotality establishes possible influence, not optimal acquisition order or net savings.
- Current experimental image/Box support belongs in a separate capability branch; keep text-only tests reproducible.

## Acceptance for the first research prototype

E0 fixtures pass in the actual implementation, raw distributions and predicate versions survive the full path, invalid/uncertain operations stay distinguishable, and a blinded outcome can be attached without rewriting the original judgment. Then run the agreed E2 comparison with matched review resources and the E1 diagnostic if probabilities will drive decisions. A plumbing pass is not a usefulness pass.

**Keep/revise/stop:** keep a use only when it improves the predeclared error/coverage/effort trade-off over the strongest feasible baseline. Revise the question or observation model when its meaning drifts. Stop the extra component when it contributes no reproducible useful information. A negative result is a completed research result.

## November 4 addendum — what changes for Cartan / Jev-01

**Keep the original first boundary and U01/U02 priority.** The later material strengthens the data and evaluation contracts. It does not require a routing framework, physical simulator or session controller in the initial builder scope. This addendum is a research recommendation; Cartan must reconcile it with the live Jev-01 contract, which was not inspected during this fold.

1. **Preserve time and provenance where relevant.** Add observation time/window, freshness, source and evidence cutoff to case records. When a rule uses history, retain the relevant history or state reference and its version. Preserve related-incident grouping for evaluation. These support session experiments without hard-coding session modes into the general interface.
2. **Use stronger comparison methods.** Include an exact Boolean rule where known; a single weighted threshold is not the whole baseline family. For session data compare ordinary rules/timeouts, an explicit history-dependent state machine, a shallow tree and a small forest when training data supports them. Jev must add measured value over these methods.
3. **Keep uncertainty meanings distinct.** Gini, vote dispersion, Jev margin, calibrated reliability, missing evidence and φ-accrual suspicion are different quantities. Gini and binary margin are algebraically redundant only when computed from the same probability. None establishes a physical edge orientation.
4. **Make observer selection optional and inspectable.** The existing acquisition record can later carry candidate capability, eligibility, selected version, rationale and outcome. Hard constraints stay explicit. Compare selection with fixed, random and cheapest eligible baselines; account for routing cost and unknown unchosen outcomes. Do not add a general self-improving harness to satisfy this research.
5. **Separate diagnosis from recovery.** A classifier result is evidence for an action policy, not authority to kill, reap or release ownership. Recovery experiments need their own preconditions and outcome design.
